# FitScouter 회의록 반영 PRD 및 검토 메모

## 1. 제품 정의

FitScouter는 사용자가 OOTD 전신 사진을 올리면 선택한 상황에 맞춰 `오늘의 패션력`, 티어, 한줄평, 상세 스탯, 보완 아이템을 제공하는 모바일 우선 서비스다. 핵심 목적은 정확한 외모 평가가 아니라 친구끼리 공유하고 비교하며 즐기는 스타일 엔터테인먼트다.

## 1-1. 아이디어 히스토리와 회의록이 나온 근거

이번 회의록의 방향은 세 가지 아이디어가 합쳐진 결과다.

황씨 아이디어의 핵심은 “점수”가 아니라 “캡처해서 공유하고 싶은 해석”이다. 총점과 등급은 첫인상용이고, 실제 바이럴은 캐릭터 한줄평, 상대 위치, 돈빨 vs 센스 같은 밈형 지표, 점수가 오르는 개선 제안에서 나온다는 관점이다. 따라서 MVP에는 단순 점수보다 `상위 n%`, `비슷한 유저 평균`, `스타일 유형`, `살짝 긁는 한줄평`, `돈빨/센스/눈치력/호감도`를 넣는 것이 맞다.

김씨 아이디어의 핵심은 “패션력 측정”의 존재감을 더 키우고, 결과를 바로 친구와 공유해서 놀 수 있게 하는 것이다. 그래서 결과 화면의 중심 언어는 OOTD 기록보다 `패션력`, `티어`, `공유 카드`가 되어야 한다. 다만 공유는 완성된 커뮤니티가 아니라 링크/이미지 공유부터 검증하는 것이 현실적이다.

조씨 피드백의 핵심은 커뮤니티 확장이 장기적으로는 맞지만, 지금은 너무 이르다는 판단이다. 실제 참고 산출물인 [FitBattle](https://fitbattle.pages.dev/)을 확인해보면 `배틀 아레나`, `갤러리`, `명예전당`, 하단 탭까지 포함된 커뮤니티형 프로토타입이다. 장점은 성장 방향이 보인다는 점이고, 단점은 초기 트래픽이 없을 때 화면이 비어 보일 위험이 크다는 점이다. 따라서 현재 FitScouter는 커뮤니티 전체를 만들지 않고 `패션력 측정 결과 공유`와 `친구 비교 링크`를 1차 검증 대상으로 둔다.

황씨 피드백의 쇼핑몰 연계는 실용성과 수익화 가능성을 동시에 만든다. “검은 로퍼를 신으면 +n점” 같은 개선 제안을 상품 검색 링크로 연결하면, 사용자는 점수 상승 근거를 납득하고 서비스는 제휴/커머스 확장 여지를 확보한다.

정리하면 현재 MVP 우선순위는 다음이다.

1. 패션력 측정 결과를 강하게 보여준다.
2. 점수보다 공유 가능한 해석 문장을 전면에 둔다.
3. 상세 스탯은 납득용으로 제공한다.
4. 개선 제안은 점수 상승과 상품 링크로 연결한다.
5. 배틀/갤러리/명예전당은 사용자 반응 확인 후 확장한다.

## 2. 사용자와 제외 범위

핵심 타깃은 만 18~34세 모바일·SNS 사용자, Instagram Story에 OOTD를 올리는 사용자, 패션에 관심은 있지만 전문 지식은 부족한 사용자, 친구들과 결과 이미지를 공유하며 노는 사용자다. 확장 타깃은 스트리트 패션·신발·빈티지 커뮤니티, 패션 크리에이터, 편집숍, 오프라인 매장 방문 고객이다.

제외 타깃은 초등학생과 시니어다. 특히 미성년자 대상 외모 평가 서비스로 해석되지 않도록 운영 문구, 광고 타깃, 공유 문구에서 주의해야 한다.

## 3. 핵심 사용자 흐름

1. 필수: OOTD 전신 사진 촬영 또는 업로드
2. 선택: 상황 입력. 예: 소개팅, 비즈니스 미팅, 운동, 친구 만남, 직접 입력
3. 결과: 사진+스티커 기반 OOTD 카드, 패션력 점수, 티어, 상위 n%, 스타일 유형, 살짝 긁는 한줄평
4. 밈 스탯: 돈빨 vs 센스, 눈치력, 첫인상 호감도
5. 상세 스탯: 실루엣, 컬러, 아이템 합, 상황 적합도, 디테일, 공유 유발력
5. 보완 아이템: 천사 아이콘은 점수 상승 아이템, 악마 아이콘은 현재 룩에서 점수를 깎는 요소
6. 상품 연결: 보완 아이템에서 무신사, 29CM 등 상품 검색 링크로 이동
7. 리플레이: 다른 상황으로 다시 평가, 데이트룩/겨울 버전 재도전
8. 공유: SNS 공유 버튼을 누르면 공유 카드 생성 또는 AI 생성형 카드 트리거 후보가 됨

## 4. 점수와 콘텐츠 톤

점수는 최대 10,000점으로 제한한다. 티어는 예시로 챌린저, 다이아, 플래티넘, 골드, 실버를 사용한다. 단, 숫자만 보여주면 공유성이 약하므로 `상위 n%`, `비슷한 유저 평균`, `스타일 유형`을 함께 보여준다. 한줄평은 “살짝 긁는” 톤을 쓰되 신체, 체형, 외모, 혐오, 성적 수치심을 건드리지 않는다. 평가 기준은 몸이 아니라 옷의 조합, 상황 적합도, 컬러, 실루엣, 아이템 디테일이어야 한다.

현재 PoC 문구 예시:

- “나쁘지 않아요. 다만 신발이 오늘 회의에 조금 늦게 온 느낌.”
- “꽤 잘 입었는데, 본인은 모르는 척할 것 같은 룩이에요.”
- “외출 금지는 아닌데, 거울 앞 추가 회의가 필요해 보여요.”

현재 PoC에 반영한 밈형 지표:

- 돈빨: 아이템 가격/브랜드 힘이 얼마나 보이는지
- 센스: 조합과 디테일이 얼마나 자연스러운지
- 눈치력: 상황/TPO를 얼마나 읽었는지
- 첫인상 호감도: 공유 카드에서 직관적으로 받아들이는 인상

## 5. 결과물 생성 전략

기본은 `기존 사진 + 스티커 + 점수 오버레이`다. 이 방식은 프론트엔드에서 바로 만들 수 있어 비용이 거의 없고, 결과 속도도 빠르다. AI 생성형 이미지는 비용과 지연 시간이 커서 모든 사용자에게 기본 제공하지 않는다.

AI 생성형 카드는 아래 트리거에서만 제공하는 하이브리드 전략이 맞다.

- 고득점 또는 S급 이상
- SNS 공유 버튼 클릭
- 기기 기준 하루 1회 무료 생성
- 추후 유료 크레딧 또는 광고 시청 후 생성

회원 없이 하루 1회 제한을 하려면 FingerprintJS 같은 브라우저 fingerprint를 쓸 수 있지만, 정확한 사용자 식별 수단이 아니고 개인정보/동의 이슈가 있다. 운영 단계에서는 로그인, 쿠키 동의, 서버 발급 익명 ID 중 하나를 선택해야 한다.

## 6. 실제 검토 결과: 로컬 모델

현재 개발 PC에서 확인한 로컬 실행 상태:

- `nvidia-smi`: 인식되지 않음
- GPU: `Intel(R) Arc(TM) 140V GPU (16GB)`로 표시되지만 NVIDIA CUDA 환경은 아님
- RAM: 약 32GB
- Python: `3.12.8`
- `torch`, `diffusers`, `transformers`, `accelerate`: 설치되어 있지 않음
- `ollama`: 설치 완료, `gemma3:4b` 모델 다운로드 완료

결론: 현재 PC에서 Ollama 기반 멀티모달 분석은 PoC 수준으로 동작한다. 다만 대형 이미지 편집 모델을 내려받아 서비스 품질로 테스트하는 것은 여전히 비효율적이다. FLUX.1 Kontext dev, Qwen-Image-Edit 같은 모델은 로컬 이미지 편집 후보가 될 수 있지만, 보통 CUDA GPU와 큰 VRAM, 대용량 모델 다운로드가 필요하다. 현재 환경은 NVIDIA CUDA가 없어 설치 자체보다 실행 품질과 속도가 병목이다.

실행 가능성 판단:

- 현재 PC 단독 로컬 실행: 비추천
- CPU 실행: 가능하더라도 속도가 너무 느려 PoC 검증 가치가 낮음
- Intel Arc/OpenVINO 변환: 연구 과제로는 가능하나 빠른 서비스 검증에는 부적합
- 현실적 선택: 이미지 생성 API 또는 클라우드 GPU endpoint

2026-06-27 추가 구현:

- 웹 PoC에 Ollama 멀티모달 분석 호출을 연결했다.
- 기본 endpoint는 `http://127.0.0.1:11434`, 기본 모델은 `gemma3:4b`다.
- 사용자가 사진을 업로드하면 data URL을 보관하고, Ollama API에는 base64 이미지로 전달한다.
- 응답은 JSON으로 받아 한줄평, 스타일 유형, 요약, 개선 포인트에 반영한다. 상세 스탯과 밈 점수는 응답 속도를 위해 앱의 기본 계산 로직을 사용한다.
- Ollama가 설치되어 있지 않거나 모델이 없으면 앱은 기본 mock 분석으로 자동 전환된다.
- `npm run ollama:check`로 샘플 사진을 Ollama에 보내는 smoke test를 추가했고, `gemma3:4b` 기준 약 45~50초 내외로 응답을 확인했다.

중요한 기술 판단:

- Ollama의 일반 멀티모달 LLM은 이미지를 이해하고 텍스트를 반환하는 모델이다.
- “검은 로퍼를 신긴 새 사진”처럼 픽셀을 실제로 바꾸는 이미지 편집 모델은 Ollama LLM만으로는 해결되지 않는다.
- 따라서 현재 PoC는 개선 아이템 클릭 시 내 사진 위에 신발/머플러/가방 레이어를 덧씌우는 가상 시착 오버레이를 구현했다.
- 실서비스급 이미지 변경은 별도 이미지 편집 파이프라인이 필요하다. 후보는 FLUX.1 Kontext, Qwen-Image-Edit, Stable Diffusion Inpainting, 또는 외부 이미지 편집 API다.

참고 후보:

- [OpenAI Image generation guide](https://developers.openai.com/api/docs/guides/image-generation): API 기반 이미지 생성/편집 후보
- [OpenAI model docs](https://developers.openai.com/api/docs/models/all): OpenAI 이미지 모델 확인
- [FLUX.1 Kontext dev model card](https://huggingface.co/black-forest-labs/FLUX.1-Kontext-dev): 텍스트 기반 이미지 편집 후보. 라이선스와 상업 사용 조건 확인 필요
- [Qwen-Image-Edit model card](https://huggingface.co/Qwen/Qwen-Image-Edit): 오픈소스 이미지 편집 후보. 로컬 실행 리소스 확인 필요

## 7. 토큰/비용 관점

서비스 비용은 두 단계로 나누어 봐야 한다.

1. 스타일 분석: 이미지 1장 + 짧은 텍스트 프롬프트로 아이템, 컬러, 상황 적합도, 한줄평, 점수 근거를 생성
2. 이미지 생성/편집: 결과 카드를 새 이미지로 만들거나 아이템을 바꿔 입힌 이미지 생성

비용 관점의 권장 구조:

- MVP: 분석 결과와 카드 렌더링은 프론트엔드 mock 또는 경량 API
- Beta: 서버에서 Vision LLM 분석만 수행하고, 카드는 HTML/CSS/canvas로 합성
- 유료/바이럴 기능: 공유 버튼 또는 고득점일 때만 이미지 생성 API 호출
- 고도화: 보완 아이템 클릭 시 이미지 편집 + 재측정 애니메이션

실제 API 토큰 사용량은 API key와 서버 구현 후 로그로 측정해야 한다. 현재 단계에서는 로컬 Ollama 분석은 실측했고, 외부 API 과금 테스트는 하지 않았다. 비용 폭이 큰 이미지 생성 호출은 기본 경로에서 제외하는 방향으로 PoC를 수정했다.

## 8. 배포처 검토

접근성 기준의 1순위는 웹 링크다. 별도 설치 없이 바로 열 수 있고, 인스타/카톡/문자 공유가 쉽다. 현재 GitHub Pages 배포 구조가 이 목적에 맞다. 운영 전환 시에는 Vercel, Cloudflare Pages, Netlify 중 하나로 옮기면 preview 배포와 서버리스 API 연결이 더 편해진다.

토스 미니앱은 접근성은 좋지만 심사 리스크가 있다. “패션 점수로 놀기”보다 “사용자의 스타일을 분석해 합리적인 패션 소비와 코디 선택을 돕는 서비스”로 포지셔닝해야 한다. 특히 토스 안에 있어야 하는 이유, 소비 최적화, 개인정보/이미지 처리, 과도한 외모 평가 금지, 실질적 가치가 중요하다.

권장 순서:

1. GitHub Pages/PWA: 즉시 배포, URL 공유, 사용자 반응 확인
2. Vercel 또는 Cloudflare Pages: 서버 API와 이미지 처리 연결
3. 토스 미니앱: “AI 기반 스타일 분석 & 합리적 패션 소비” 버전으로 별도 심사용 화면 구성
4. Expo/EAS 기반 앱스토어·플레이스토어: 반복 사용, 갤러리, 로그인, 푸시가 필요해질 때 진입

커뮤니티형 기능의 판단:

- 지금 넣지 않을 것: 배틀 아레나, 공개 갤러리, 명예전당, 팔로우/피드
- 지금 검증할 것: 공유 카드, 링크 기반 친구 비교, 같은 사진의 상황별 재평가
- 나중에 넣을 조건: 최소 반복 사용 지표, 공유 전환율, 친구 초대율이 확인된 뒤

## 9. 다음 검토 과제

- 실제 API 기반 분석 20~50건 샘플 테스트: 점수 분포, 한줄평 강도, 실패 케이스 확인
- 카드 합성 방식 결정: HTML/CSS 캡처, canvas, 서버 이미지 렌더링 중 선택
- 상품 추천 방식: 검색 링크, 제휴 링크, 자체 큐레이션 중 선택
- 사진 저장 정책: 기본 미저장, 사용자 동의 시 갤러리 저장
